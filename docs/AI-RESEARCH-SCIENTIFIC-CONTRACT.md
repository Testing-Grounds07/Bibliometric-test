# Research-to-interface scientific decisions

2026-10-20. Proposed integration behavior grounded in the existing reviewed BNR R5/R12 packets and current implementation. Numerical fixture verification, app usability and human scientific assessment are separate gates. This document precedes development of source acquisition, appraisal and new method controls.

## Evidence acquisition and specialist appraisal

Keep search discovery, metadata retrieval, source acquisition, text extraction, appraisal and synthesis distinct. A successful download is not successful extraction; extraction is not substantive appraisal. An imported passage must not be represented as an independently acquired article. A title/abstract record remains metadata/abstract evidence even when an HTTP request completed.

Source contracts retain provider/work/DOI identities, requested and final allowed endpoint, timestamp, byte hash, content type, access result, license when known, extraction version, extracted-text hash and explicit truncation/missingness. Never archive credentials or secret-bearing query strings. Resolve only configured providers and validated opaque work identifiers. Redirects, decompression, response bytes, decoded text and total source count require independent caps. Deny entity expansion/external XML resources. Preserve partial/error attempts. Unknown license stays unknown.

Primary provider documentation inspected: [OpenAlex fulltext](https://help.openalex.org/access/fulltext/). Work-ID content routes resolve archived documents; publisher PDF locations do not identify archive objects. Parsed TEI can contain missing/duplicate material and may fail for scans. Both content identity and extracted-text identity are needed. Existing historical raw scholarly documents can be used as frozen imported fixtures, with their acquisition provenance preserved.

The Europe PMC REST documentation fetch returned403 in this research pass; no new implementation contract is inferred from its search snippet. Implement a provider only after its actual documentation/response behavior is verified. An unavailable provider need not prevent importing already acquired, hash-verified source artifacts.

Appraisal records are source- and question-specific: study design, population, intervention/exposure, comparator, actual outcome/construct, instrument, rater, timing and baseline, analyzed denominator, attrition, allocation, dependence/clustering, results, contradictions, limitations and exact source locations. Unknown fields remain unknown. Store review overlap/cohort dependence and contradictory results rather than automatically summing samples or selecting favorable estimates.

[PRISMA-ScR](https://www.prisma-statement.org/scoping) supplies reporting guidance for evidence selection and charting, not a guarantee of comprehensive discovery or a universal quality score. [Cochrane chapter8](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-08) concerns risk of bias in particular randomized-trial results. Neither justifies calling a generic extraction schema a validated bias assessment for all designs. The integration offers structured evidence appraisal; specialized tools require their appropriate study designs and complete procedures.

Specialists receive bounded question/source packets and isolated sessions. Their proposals, actually executed actions, source excerpts and final appraisals are distinct artifacts. The lead records representative and contrary evidence, unexamined material and disagreement. Independent methods/statistics reviewers retain their own scope and cannot inherit a specialist's self-check as independent verification.

PDF import must use the original bytes with independently hashed extraction and one-based page locators. [pypdf text extraction guidance](https://pypdf.readthedocs.io/en/stable/user/extract-text.html) distinguishes digitally stored text from OCR and discusses memory costs of decoded content. Keep supervised wall-time/RSS/raw/decoded/text limits and explicit no-OCR/reading-order limitations. Large raw PDFs enter through bounded opaque upload chunks, not arbitrary remote filesystem paths or a model prompt.

The first real-paper ingress test failed honestly when repeated missing-font warnings exceeded the parser's diagnostic cap; this was not a successful extraction. Before the dependency repair, inspected pinned pypdf6.21.1 package metadata and its [CFF mapping implementation](https://github.com/py-pdf/pypdf/blob/6.21.1/pypdf/_cmap.py): the `fonts` extra requires fonttools, whose CFF parser supports those encodings. [fontTools documentation](https://fonttools.readthedocs.io/en/stable/index.html) describes the relevant CFF library. Pin the specific font dependency and retain parser warnings rather than hiding them or changing the output cap to disguise failure. Font support still does not establish correct table interpretation, article identity or semantic appraisal.

### Specialist output contract repair

The second real-role pilot produced an appraisal list plus three undeclared fields inside the generic response's JSON string. Strict runtime validation rejected that output; the original failed chart must remain failed. For the next revision, give this fixed specialist role a directly typed, nested appraisal schema rather than hiding its scientific result in an unconstrained string. Do not strip fields from the retained failed answer and present it as an accepted historical appraisal.

Current [official Codex evaluation guidance](https://developers.openai.com/blog/eval-skills) demonstrates enforcing nested final responses through `codex exec --output-schema`. The [Structured Outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses) requires declared object properties, all required fields and `additionalProperties: false`; nullable values can preserve unknowns. Use the supported schema subset and test the actual pinned CLI. Retain local checks for exact source/segment identity, quote matching, bounds, complete field coverage and known usage even when an answer fails. Structured shape is not semantic entailment or human expertise. This is an implementation decision inferred from those documented facilities and the actual failed output, not a claim that the current pilot passed.

Independent inspection also found literal quote mismatches in both failed specialist attempts. A strict outer schema alone does not resolve those errors. The fixed role may select opaque IDs from a deterministic catalog of exact excerpts: retain source ID, original segment ID, declared character offsets and text hash, and construct chart quotations from the original retained text. Partition every selected segment contiguously with no dropped or invented characters; these fragments are a citation mechanism, not automatically representative evidence or linguistic sentences. Reject unknown IDs and cross-source references. The original evidence and failed answers remain unchanged. Exact excerpt selection still requires independent review of whether the passage actually supports its assigned claim.

After a successful chart, expose a complete bounded public projection to the lead and fresh reviewers, including every field, unknown, evidence reference and coverage qualifier. Exclude private assignment rationale. Deduplicating repeated exact excerpts or moving a source locator index to explicit retrieval can reduce context without changing evidence; truncating chart fields or source coverage silently cannot. Preserve the original full chart and source hashes regardless of the display projection. Oversized scientific context requires explicit paging or an honest bound failure.

## Method interface acceptance

| --- | --- | --- |
| Constraint | Undirected positive weighted graph; local redundancy, not established knowledge brokerage | Unweighted 3-leaf star: center1/3, each leaf1; isolated node undefined |
| Harmonic centrality | Explicit unweighted or inverse-similarity paths; disclose direction and boundary | Undirected 3-leaf star unweighted: center3, each leaf2 |
| Eigenvector | Weight/direction, tolerance and iteration bound; retain residual/nonconvergence | Connected regular tiny graph uniform L2-normalized vector; failed solver has no replacement |
| Rich-club density | Nodes with degree strictly greater than cutoff; raw induced density | Star cutoff0 gives density1/2; cutoff1 has only hub, so undefined; no enrichment claim |
| Shared-node multilayer | 2–20 undirected graphs, exact same typed node IDs, explicit weights/gammas/seeds/iterations | Different IDs or directed layer reject; independently recompute achieved joint CPM, no global optimum claim |
| Joint temporal | Explicit ordered slices, variable membership allowed, gammas, omega, seeds and iteration bounds | Only same-ID nodes in adjacent slices receive coupling; retain per-slice membership and coupling quality |
| Custom core/periphery | Explicit exhaustive/bounded seeded ideal-pattern solver; degree confounding | Three-node star can fit SSE0 with central core; no significance or named alternative algorithm claim |
| Triad census | Binary policy, direction and complete node universe including isolates | Sum16directed classes or4undirected counts equals choose(n,3) |

## Interpretation and display

Expose the question answered, input coverage, effective settings, output meaning and material limitation next to the relevant action/result. Keep optional technical details inspectable. Undefined metrics display as unavailable with reason, never zero. A display threshold does not change membership or imply recalculation. Labels/colors do not establish themes, persistence or influence.

Same OpenAlex IDs with different reference observations are different evidence. Cross-backend comparisons first require matching corpus, graph kind, thresholds, weights, objective and node universe. Numeric cluster labels may differ; compare partitions rather than label numbers. Identical objective conventions can differ by a documented factor. The app must show incompatible comparisons instead of silently intersecting unless intersection was expressly selected.

Research status reports raw/retrieved/selected/eligible/analyzed/displayed counts separately, partial search/acquisition, actual reviewer roles, executed checks, outstanding objections and human expertise status. Completion is conditional on the claims actually made; an honest insufficient-evidence finding may complete.

## Snapshot expansion and evidence versions

Expansion creates a new immutable evidence version linked to its parent and the exact acquisition chain. Keep the original query, literal matching semantics, intended inventory, unavailable files, inspected rows, limits and continuation boundary. A completed scan of available files is not a complete provider snapshot when declared files are missing. Selecting a continuation chain retains every matching physical observation, including repeated work IDs, before the normal explicit identity/eligibility stage. These rules follow the existing reviewed R10 connector contract; the root six-row MCP pilot independently exercises them.

Compare evidence observations separately from graph/backend comparisons. Report raw observation counts, distinct normalized work IDs, added/removed IDs, and common IDs whose retained record observations differ. Compare the complete multisets of frozen record fingerprints for each common ID; choosing one duplicate as the definitive record would hide changes. A reference-list change is a changed observation even when ID membership is unchanged. Field-level differences can explain the change, but do not by themselves establish which observation is historically correct. Missing and empty references remain distinct evidence states.

Preserve unchanged parent evidence, its jobs/findings and reviewer bindings. New graph computation and interpretation require a deliberate operation on the selected new version. The existing cross-backend comparison must continue rejecting mismatched evidence/settings; an evidence-version difference report must not make those graphs scientifically equivalent or silently reuse old analysis.

## Explicit existing-result attachment to research

The accepted M4 pilot starts from frozen raw evidence and retained sources. External project MCP tools can inspect app results, but that alone does not attach those results to the internal tool-disabled lead. Complete the planned existing-result interface through an explicit, typed attachment operation, shared by the app and MCP.

Resolve selected original or method results through current project authorization, then freeze exact result/artifact bytes, checksums, backend, settings, parent evidence and typed universe in the research material binding. Use opaque attachment IDs and bounded reads; no arbitrary paths, live project lookup from the model, silently truncated graph or unverified user-context substitution. Retain original reports and their own review status. Reading a prior calculation does not become a newly executed check.

Compact orientation should identify the attached analysis, coverage, actual operation and available exact sections. The lead and fresh reviewers may retrieve the corresponding archived pages without private assignment rationale or other reviewers' opinions. Candidate/review bindings include the immutable attachments. A changed attached result or scientific input invalidates the corresponding review binding. Same-project membership is necessary but does not establish compatible evidence: require matching selected evidence/lineage, or an explicit version-comparison context that keeps the different universes separate.

## Pause and retry semantics

The research workspace must offer a durable pause after the current bounded step, followed by explicit resume. An already running provider response is not suspended or free of cost. Preserve its real completion or unknown-usage state before stopping additional steps. Pause/resume controls alter operational intent, never the frozen candidate, review or evidence bytes; reads distinguish current control state from the last archived step.

An explicit retry links a new bounded request to a known failed, retryable operation and retains its failure, checkpoints and already-spent costs. Exact-key replay remains idempotent rather than launching a second inference. Unknown accounting, cancellation, qualified completion, exhausted budgets and changed source/configuration retain their separate guards. Do not implement retry by erasing the failed attempt or resetting a study. These are the concrete pause/retry meanings of M4.1 and M3.2, not a promise of native process suspension.

## Immutable evidence-version comparison interface

The version comparison uses the reviewed raw-observation multiset profile. Group records by explicit normalized OpenAlex work ID, while fingerprinting each original stored JSON object before introducing version IDs or locators. Object key order is neutral; every array order, missing/null/empty value and duplicate multiplicity remains observable. Even differently represented raw IDs can change an observation within the same normalized identity group. This is a comparison of stored observations, not bibliographic semantic equality or graph compatibility.

Read both versions through the same current project authorization and check authorization again before returning. Bind original artifact checksums and acquisition descriptors. Bound each evidence read to24MiB,10,000 physical rows and20MiB of canonical records, with a64-level JSON nesting bound. Reject overflow explicitly; no records are sampled. These are interface resource bounds, not scientific thresholds.

Summary counts distinguish physical rows, distinct IDs, added/removed/common/changed ID groups and matched/added/removed physical observations. Exact ID pages carry row counts and multiset hashes. A separate observation page names one canonical work ID and pages every fingerprint and its before/after multiplicity; a single ID with10,000 variants must remain inspectable. Original before/after raw rows remain accessible through their existing protected evidence pages. Comparison is a read: it creates no search, analysis job, new evidence version or altered parent. Broader acquisition, eligible/analyzed/displayed universes and network comparability remain separate operations.
