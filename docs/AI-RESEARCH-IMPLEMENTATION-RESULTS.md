# BiblioMap AI research integration: local implementation results

The local 0.4.0 development release is complete. All 29 local milestones passed their scoped developer, independent reviewer and primary-agent usability gates. M6.7 remains an external activation gate. Development used `feature/ai-research-integration` in BiblioMap and the same branch name in the sibling researcher repository. Changes remain uncommitted; existing dirty and staged work was preserved. The researcher repository still has unborn Git history.

| Milestone | Delivered behavior |
| --- | --- |
| M1 | Versioned scientific exchange, exact evidence/result/settings lineage, compatibility checks and explicit unsupported cases. |
| M2 | Protected personal project adapter and separate shared authenticated MCP resource boundary; live project authorization, scopes, distinct issuer/subject routing and revocation. |
| M3 | Frozen evidence import, bounded jobs, idempotency/cancel/retry, native result inspection/findings and same-universe backend comparison. |

| M6 local | Configured snapshot catalog/search/continuation/new immutable evidence versions, exact physical-record version differences, pilots, browser accessibility checks, matched recovery, packaged runtime and installed-skill refresh. |

Broad regressions passed: **497 BiblioMap tests, one skipped; 140 researcher tests plus six subtests**. Independent checks covered the actual 951-work graph (10,891 edges and 655 isolates), method outputs including actual MiniLM layers, project/identity denials, source/candidate bindings, exact attachments and immutable acquisition chains. Desktop and mobile-sized browser checks exercised ordinary controls, keyboard navigation, filtering, startup and late-response races. These are bounded software/mathematical tests, not screen-reader/WCAG certification or expert scientific validation.

The real two-paper research pilot used eight provider sessions and spent 212,481 tokens. The original 180,000-token attempt failed honestly; an explicit owner amendment to 250,000 preserved spent usage and frozen reviews before the final lead call. The later attachment/control/recovery/snapshot UI checks made zero new provider calls. No comprehensive leadership-literature review is claimed for this two-paper pilot.

A matched offline backup of the fresh task-owned Neo4j instance, including the system database, was restored into a new volume. All 1,433 user-database nodes and 988 relationships matched before reopening; all artifact/workspace file hashes matched. A fresh app reopened exact reports, sources, findings, graph/method results, attachments and snapshot/version records with **no engine, no coordinator and zero new jobs**. Both root-owned recovery database instances were stopped after verification. Existing services were not restarted. This is local fixture recovery; production/offsite recovery and automatic relocation of unfinished execution are unassessed. A changed execution profile uses an explicit parent-linked new session and deliberate source reimport/reselection.

The installed skill was backed up, refreshed to the exact 0.4.0 archive, and checked through actual CLI and official SDK calls outside the checkout. All 143 package members match; operator-local configuration is unchanged. Wheel, skill ZIP and plugin ZIP runtime/resources match independently audited source. Earlier distributions, failed attempts and exact reviewed source snapshots remain retained.

Actual institutional registration/login/consent, deployed TLS resource configuration, an actual ChatGPT account tool call, and production matched backup/cutover remain external steps. The running production platform and existing tunnel were not activated by these local tests. Human expert interpretation and any unperformed full scientific replication remain unassessed. Prior-result attachments expose exact scientific material; they do not automatically rerun arbitrary attached graphs. Available snapshot-scope completion does not establish a whole-snapshot census.
