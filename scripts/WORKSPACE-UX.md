# Canvas workspace review

## Score and search controls

Direct hypergraph modularity now additionally offers **Group moves · experimental** and **Annealing · experimental**. Both preserve the selected objective, resolution, evidence weighting and ten-start budget. Group moves performs greedy vertex refinement, then whole neighboring-community merges and vertex readjustment for at most four rounds. Annealing performs twelve degree-scaled cooling sweeps (0.2 to 0.002), can accept downhill moves, retains the best encountered state, then polishes it with greedy vertex moves. The existing mixed/Leiden-seeded searches remain unchanged. New choices are preserved through tab state, settings scans, reliability, exports and canonical computation identities. Scans retain the selected search; they do not silently select another optimizer.

These are bounded custom heuristics, not native Leiden/Infomap optimization of direct modularity and not the published h-Louvain implementation. The latter blends graph/hypergraph objectives and uses a tuned schedule: [Kamiński et al., 2024](https://doi.org/10.1093/comnet/cnae041). Whole-community search with original hyperedge information is also discussed by [Chodrow et al., 2021](https://arxiv.org/abs/2101.09611). Bibliomap keeps its own score unchanged. Annealing convergence flags describe only its final greedy refinement, not convergence of the cooling process or a global optimum; its fixed budget and accepted downhill moves are recorded. Group rounds reaching the cap are flagged nonconverged. Reliability still uses two starts per resample, not the ten-start main fit, and is structural sensitivity rather than thematic validation.

Validation status distinguishes settings searches from evidence checks. A finished scan reports its stable-range outcome even without a reliability result, then hands off to a single preliminary evidence check when the same map remains active. Failures and cancellations expose retry states rather than reverting to Not checked. Dataset updates are observed, including progress; status refreshes never launch computation.

Validation is a compact toolbar menu, separate from representation, score and search. Quick (10) and full (50) checks rerun the existing evidence-reliability workflow without changing the map; Find stable settings runs the existing settings comparison with fresh finalist validation and may apply a confirmed setting. Its status summarizes the full map, not the selected cluster, and preliminary results remain marked. Results and technical details open the existing floating Analysis panel without displacing the canvas. Unsupported, pending and viewer-only actions are disabled; redraws never initiate validation.

The shared toolbar now reads **Network model → Score → Search**. CPM maps to Leiden, the map equation to Infomap, and model description length to nested SBM fitting. Single supported searches stay visible but disabled; the control does not imply that arbitrary objectives can be passed into every optimizer. The existing hidden `clusteringMethod` remains a compatibility adapter for saved maps, project APIs and tab state. New controls derive from its value and completed graph metadata without submitting computations on redraw.

Direct hypergraph modularity offers **Local moves · mixed starts** (the unchanged default) and **Local moves · Leiden starts**. Both run multi-start direct vertex-move optimization of the same whole-combination objective. The latter replaces all initial guesses with Leiden-generated partitions of a temporary projection. It is not native Leiden optimization of hypergraph modularity and does not inherit Leiden refinement/connectivity guarantees. Search choice is retained in result metadata, settings/reliability runs, exports and server fingerprints; unknown strategies are rejected.

Analysis → **Score, search & audit** explains score, search steps, restarts, Auto parameter selection and evidence reliability separately. Cluster headings follow completed result metadata, not a stale stored label. While a new co-citation result is pending, the old cluster heading explicitly says **Previous result**. No research data or historical findings are migrated by this interface change.

Project saving and OpenAlex retrieval now share the floating Projects tool. See `WORKSPACE-PROJECTS.md` for persistence, search provenance, new-corpus mapping and local service details.

Three reviewer/planner cycles on 16 October 2026 reorganized the existing Atlas controls around the graph. The analysis calculations, saved inputs, scientific settings and graph interactions are unchanged.

The workspace shell runs after the Atlas application and moves the existing controls, preserving their IDs and handlers. Analysis contains scope, order, CPM, Auto settings, reliability and coupling configuration. Display contains cluster visibility, labels, sizes, colors and line filters. Search retains the article list and search draft. Inspect contains selected evidence and shared foundations. Existing reveal actions open the appropriate panel before focusing their target. More retains appearance, animation, exports, mobile expanded-map control and the coupling evidence export.

Closed panels are removed from keyboard navigation. Buttons expose `aria-controls` and `aria-expanded`; Escape and Close return focus to the toggle. Opening a tool focuses its Close button. Tools float over the right side of the map with an independently scrolling body and a persistent heading. Phones use a bottom sheet capped at 60% of the viewport. Opening or switching tools does not reflow or resize the canvas, including in expanded mode. Method loading/failure messages remain visible outside panels. All main tool buttons retain 44px touch targets; the cluster strip retains its horizontal scrollbar.

## Visual design follow-up

The agents considered three directions: Precision Observatory (crisp navy surfaces and restrained cyan accents), Light Research Studio (bright neutral surfaces for long reading), and Orbital Instrument (more atmospheric indigo, glass and luminous ornament). Observatory was selected for the default night appearance, with Studio available through the existing Night mode control. No additional style picker was added. Cluster colors, graph coordinates, weights and analytical behavior remain unchanged.

The tester reports observed visual and interaction results; the feedback/ideation agent gathers those findings and recommends changes; the primary agent implements them. This separation also applies to subsequent style reviews.

`workspace-theme.css` supplies accessible dark/light text and surface colors, system sans headings, quieter inactive controls, active cyan/violet underlines, and consistent tile, menu and dialog treatments. Motion is limited to 180ms panel/menu entrances, hover/press responses, a small progress indicator while real work runs, and the Atlas's existing graph/exploded animation. No ambient particle, blur or layout loop was introduced. Pause motion and system reduced motion disable UI animation and hover/press movement; paused exploded dialogs close immediately. The motion control uses action labels (Pause motion / Resume motion) without contradictory toggle semantics.

## Sculptural minimalism

The neutral theme is applied in the initial HTML. A matching loading screen covers the unrearranged controls while data scripts load, then disappears when the shared workspace finishes mounting. Startup script failures retain that screen with a reload action. The loading indicator respects reduced motion; AI descriptions and reliability continue in the background after the canvas is visible.

The selected mockup is implemented as a light, neutral default with monochrome controls, gray focus/selection states, rounded white surfaces and restrained shadows. Night mode remains available with neutral charcoal surfaces. Color is reserved for network data and matching cluster swatches. Existing graph memberships, node metrics and analytical inputs are preserved. The workspace tabs now share the masthead, and existing map tools share one wrapping toolbar. All four tools use the same floating panel, preserving the map's dimensions. Network controls use a compact grid; detailed Auto reasoning and reliability counts live in their existing disclosures, with uncertainty and progress still visible.

Connections use quadratic curves with uniform 1.5px visual strokes and invisible 12px pointer targets. Within-cluster lines use their community hue; cross-cluster lines are gray. Their color intensity is encoded as `0.12 + 0.8 × log(1 + weight) / log(1 + full-analysis maximum)`. Weight means shared-reference count for coupling, supporting source count for a single co-citation order, and the experimental combined score for all orders. Display filtering never rescales the intensity domain. Overlapping colored links provide a heatmap-like impression, not a statistical density estimate; nodes retain their individual shapes and existing size/color encodings. Focus/search can separately dim unrelated evidence. A dashed selected connection identifies selection without repurposing thickness as weight.

`network-appearance.js` shares stable curve geometry between strokes, pointer targets and moving evidence dots. Line inspection, keyboard selection and long-press targets use the same `data-edge` group. The intensity legend includes its numeric domain and metric; exact values remain in the line inspector. Appearance/curve unit tests supplement the existing shared-canvas/navigation/touch suite.

Validation: 24 targeted tests pass. The exploded connection dialog follows the same neutral appearance: light gray stage, raised neutral sheets, monochrome controls and readable evidence disclosures. Node colors are supplied by the main map instead of hardcoded anchor/other colors. Layer links are curved and indicate exact combination membership, not the main map's intensity metric; A–B is identified by dashes. View framing adapts to the number of layers so single combinations stay centered. Order selection, paging, supporting evidence, keyboard focus return, animation and reduced-motion behavior are preserved. Phone layouts stack the stage and evidence with a sticky return header.
