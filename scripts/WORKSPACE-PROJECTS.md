# Projects and OpenAlex in the canvas

The Projects tool shares the floating workspace panel. It lists Neo4j projects, search history and saved findings. A finding records the complete canvas snapshot, graph, memberships, clustering/settings audits, completed reliability results, filters, selection, zoom, available generated labels and researcher notes. Search terms, phrase mode, date bounds, retrieval cap, retrieval time, total matches and actual retrieved count remain linked through the search and corpus records. Save creates a new immutable analysis; opening one restores it without rerunning the original search.

OpenAlex search uses the server's `OPENALEX_API_KEY`. The browser never receives the key. Searches page through `/works` with cursor pagination, deduplicate work IDs, and stop at cursor exhaustion or the explicit cap (1–20,000). The UI distinguishes partial results from complete retrieval. Cancel aborts retrieval; incomplete results are not presented as a completed saved search. The server keeps short-lived progress jobs in memory; completed searches and findings persist in Neo4j across service/browser restarts. A service interruption can lose an unfinished job.

Search results retain the retrieved OpenAlex metadata and references. Building a map creates a derived corpus using the existing Conservative, Balanced or Inclusive metadata preset, with included/uncertain/excluded counts and human validation set false. No topical screening is implied. Existing curated source corpora are preserved. Saving an existing map into another project copies its corpus and links its original search provenance.

New searches open as pairwise co-citation with adjustable reference frequency, joint source support, and CPM. Blank CPM starts at scaled network density divided by four; it is labeled exploratory. Find settings and method-specific reliability are available in Analysis. The existing Leiden, Infomap, hypergraph and nested block-model options operate on the selected evidence. Coupling uses that corpus's available reference lists in the same canvas. Strict cluster drill-down keeps the source corpus and restricts the reference set; Return to full search network rebuilds its parent scope. Co-citation maps are limited to 1,500 eligible references and 100,000 connections with an explicit instruction to raise the minimums rather than silently truncate.

The original adaptive-leadership map retains its higher-order data, cached MiniLM/KeyBERT and verified AI descriptions. New searches default to preparing higher orders, keywords and Qwen names when their map is opened. Users can opt out, generate later in Analysis, cancel, or rerun generation without using a terminal. Progress appears in Analysis; Qwen naming runs sequentially beside the cluster strip with pause/retry/rerun controls. Computation runs on the hosting PC, not on the visiting phone or tablet. Missing reference metadata remains an OpenAlex ID, never a manufactured title.

## Work-level deduplication

Newly built maps deduplicate source works and cited references before computing frequencies, coupling, exact bundles, communities or reliability. Same DOIs match after URL/case normalization, including the known APA `10.1037//` formatting variant. Otherwise a title must have at least three words and 20 characters, matching author lists and compatible known publication types. Case, punctuation, accents and ampersands are normalized. Titles of at least eight words and 60 characters can differ by at most two character edits, without conflicting DOIs or numeric tokens. All members must match each other; fuzzy chains cannot join unrelated records. Non-book title matches require recorded years within two years. Conflicting article DOIs stay separate except matching JSTOR / Academy of Management aliases with matching titles, authors and compatible years. Reviews without a shared DOI, unknown publication types, missing-author matches and materially different titles stay separate. This is conservative record linkage, not proof that every similar title is the same work.

Matching requires available metadata; unresolved OpenAlex IDs are retained, not guessed. Project maps inspect metadata for references occurring at least half the selected citation minimum, prioritizing frequency, up to 5,000 records; this catches versions that separately fall below the analytical threshold. The audit records the candidate cutoff, coverage and any cap. Uninspected lower-frequency versions can remain separate. Original search/corpus records remain unchanged. Canonical works retain every original ID, title, DOI and recorded year. Labels show combined years (for example, 1994 / 2009), with a combined-record note and provenance in inspection. Reference lists and source support use sets, so one source contributes once even when it lists multiple versions. The deduplicated evidence is also used by bibliographic coupling and method-specific resampling. Saved findings keep their historical analysis; opening an older map asks users to rebuild from its search rather than silently changing its memberships.

`node scripts/rebuild-deduplicated-atlas.mjs --audit-only` previews matches in the adaptive-leadership corpus. `--publish` rebuilds its default networks, closed bundles, expanded drill-down evidence and complete Auto CPM bootstrap audits before publishing a coherent dataset. Original assets are backed up under `.trials/conservative-cocitation/deduplicated-v1/original/`. No historical finding or raw Neo4j record is deleted or overwritten.

`node --env-file=.env.local scripts/clean-project-results.mjs <completed-retrieval-directory>` audits a previously downloaded project with the same matcher, checkpoints reference metadata requests and registers its cleanup on the original Neo4j search. The original works, native citation observations, search terms and retrieval counts are preserved. Project history and search preview show the post-cleanup source count. Newly built maps apply the registered identity map after the selected eligibility filter and use a separately named derived corpus; earlier findings stay unchanged. Metadata aliases are included when building the reference scope so combined-year provenance survives. The cleanup audit and reusable metadata cache live under `.trials/workspace-search-cleanups/<search-id>/`; back up this directory with Neo4j. A cleanup does not itself generate a map or bypass network size limits, and it does not claim all unresolved cited-reference IDs were matched.

Generation mines exact closed frequent co-citation bundles over the selected reference universe and joint-source minimum. Closed bundles losslessly represent supported subsets through the largest supported N. Single-order projections union distinct source IDs; combined scoring counts each source once using its largest supported bundle, capped by the maximum-order slider. Neither overlapping combinations nor layers multiply a source's contribution. Mining fails explicitly at 50,000 closed bundles or three minutes without publishing partial mining results; users can increase the minimums. Keyword generation has a 20-minute limit. Cancellation preserves completed artifacts; unfinished jobs do not survive a service restart.

MiniLM/KeyBERT reads source titles/abstracts and fetched reference titles/abstracts; embeddings use the pinned model revision and shared SQLite cache. Per-corpus artifacts live in `.trials/workspace-corpora/<corpus-id>/`, keyed to reference incidence and support. Completed bundle and semantic artifacts are written atomically, reused across CPM/method changes and copied when a corpus is saved into another project. Neo4j records the artifact manifest; saved analyses retain the exact graph, bundles, generated descriptions and view state. Back up both Neo4j and the artifact directory. Qwen uses the same evidence-verification and repair rules as the original map: literal excerpts and distinct member works are checked, but thematic accuracy remains a researcher judgment.

Display offers Articles / Authors, Cluster Keywords and Qwen Cluster Headings. Semantic modes show one representative label per visible cluster, fall back to keywords while Qwen is pending, and restore article labels on node hover/selection/search. Hover or keyboard-focus a cluster label for its Qwen description; click/tap or press Enter to inspect the cluster, text evidence and regeneration controls. Labels do not change memberships. Return to adaptive leadership map restores the original dataset; saved snapshots also restore label mode and higher-order settings.

## Local service

## Workspace URL paths

`/conservative-atlas/projects` opens project selection; `/conservative-atlas/projects/<project-id>` opens one project's history. Live maps use `/conservative-atlas/map` or `/conservative-atlas/projects/<project-id>/map`. Cluster exploded views append `/clusters/<cluster-id>/combinations`; pair-anchored views append `/connections/<encoded-source>/<encoded-target>/combinations`. Opening and closing these views updates the address automatically without saving a finding or copying a link. Scrolling does not add combination parameters to new URLs.

URL paths describe navigation, not a bookmark of unsaved settings. Same-tab Back/Forward retains the live canvas; a fresh project URL asks users to open a saved map or build their search rather than reconstructing unsaved analysis. Save current map remains a separate, explicit action. Existing saved maps use `/conservative-atlas/projects/<project-id>/maps/<analysis-id>` and still restore their snapshot and exploded view, including legacy combination parameters. Missing projects/maps and mismatched identities report an error instead of showing unrelated data. These paths do not change the existing tunnel/API access policy.

The local host's `analysis-proxy.mjs` recognizes only the supported route grammar and serves the same index; `workspace-route-path.mjs` must be deployed beside it. A fixed HTML base keeps assets and APIs rooted at `/conservative-atlas/` at any route depth. Rebuild `scripts/workspace-routing.mjs` as the `public/conservative-atlas/workspace-routing.js` IIFE after editing. Unsupported/static/API paths are not swallowed by the page fallback.

## Canvas views

Display → Appearance & lines → Representation switches between the standard network and hyperedge envelopes without changing clustering or reliability. Selecting Hypergraph defaults to envelopes. Co-citation uses exact supported combinations reconstructed from closed bundles; coupling uses whole source groups citing one shared reference, not co-citation bundles. Only complete visible groups of three or more members are drawn. Selected nodes, connections and clusters narrow the overlays; at most 60 are shown, with the eligible total reported. Co-citation prioritizes source support; coupling uses deterministic reference ordering and equal intensity because each shared reference has unit weight. Outlines can enclose non-member nodes: hover/focus highlights exact members and activation opens the member/evidence inspector. Representation is retained in saved canvas findings and per-tab snapshots; old layered-canvas findings migrate to envelopes.

Cluster actions → Explode cluster combinations opens the existing animated exploded-view dialog and styling, leaving the main canvas unchanged. Each layer is one exact within-cluster combination (or one whole shared-reference group for coupling), not an order or a cluster boundary. Both cluster and connection views scroll continuously, lazily appending four layers near the bottom; a Load more button also supports keyboard operation. Existing layers are never replaced or reanimated during scrolling. Changing combination size intentionally starts a fresh scope. Article coordinates and identity markers remain fixed throughout that scope. Dotted vertical guides connect identity, filled nodes mark membership, and up to 24 hollow context nodes repeat across planes. Layer selection shows exact members and provenance; dotted leader lines connect its article list to visible corresponding nodes and update on scrolling and resizing. Hover, focus or activate a member row to emphasize or locate its node. Counts overlap and must not be summed. The cluster preview ranks up to 2,000 complete combinations by support, explicitly reporting omitted groups; crossing-cluster groups are not clipped into smaller fake groups. Envelope inspection also offers Explode this combination. The original pair-anchored connection inspector remains available. Reduced-motion preferences disable entrance animations without losing the static separated layout.

The exploded renderer's editable source is `scripts/exploded-view.mjs`; rebuild its published IIFE with `npx esbuild scripts/exploded-view.mjs --bundle --format=iife --outfile=public/conservative-atlas/exploded-view.js`.

Track article selects an article across the entire exploded scope and keeps its node and vertical identity guide emphasized as layers load. When absent from a combination, it appears as a hollow context node and in a separate card below the combination articles; when present, its existing member row receives a Tracked badge without duplication. This never adds the article to a combination or changes supporting-source counts. Clearing the selector restores ordinary context nodes.

Scrolling the layer pane automatically focuses the visible sheet nearest its center, updating the evidence panel and dotted article leaders. A 12-pixel deadband prevents selection flicker at boundaries. Pointer hover does not override scroll focus. Clicking or keyboard-focusing a layer still provides an accessible manual alternative and centers it. Leading/trailing spacing allows the first and last sheets to reach the center. Newly appended layers do not restart existing animations, and restoring a legacy saved link centers its exact selected combination. Focus calculations use settled sheet geometry so the entrance animation does not move the selected target.

For full cursor-exhaustion imports beyond the interactive cap, run `node --env-file=.env.local scripts/retrieve-openalex.mjs <checkpoint-directory>`. Optional environment variables `RETRIEVAL_QUERY` (include quotation marks for an exact phrase), `RETRIEVAL_FILTER` and `RETRIEVAL_PROJECT_NAME` select the search and project; defaults retain the original adaptive-leadership import. Each page is checkpointed for resumption with the same query and directory. Full metadata, the untrimmed corpus and native citation relationships are saved in Neo4j; no map or semantic generation is run automatically. Source-level CWTS Core restriction uses `primary_location.source.is_core:true` in the filter and is distinct from the OpenAlex `core` catalogue selector.

Run `scripts/start-workspace-projects.ps1` from this repository. It launches `scripts/workspace-projects-service.mjs` hidden on localhost:8094, using `.env.local` for Neo4j and OpenAlex configuration. Logs and PID are in `.trials/workspace-projects/`. `GET /health` reports availability without credentials. `scripts/analysis-proxy.mjs` forwards only the supported `/conservative-atlas/workspace-api/` project/search/map routes from the existing host. The service does not expose arbitrary upstream URLs or database queries.

Project/search listing uses native summary properties and counts so opening the panel does not deserialize every large historical network. Full saved payloads remain in existing Neo4j records, with native corpus citations and analysis relationships maintained by `Neo4jStore`. The service adds `workspace_summary`/`workspace_version` projections for its newly created records; earlier analysis formats are not presented as restorable canvas findings.

Targeted unit tests: `node --test scripts/workspace-projects.test.mjs scripts/project-higher-orders.test.mjs scripts/description-queue.test.mjs`. Mining is compared against exhaustive itemsets, including randomized incidence patterns. Browser validation covers a capped real OpenAlex search, automatic full preparation, higher-order controls, cancel/rerun, both label modes, Qwen keyword tooltips, cluster details, and saving/reopening co-citation and coupling findings. Restored descriptions with matching request scopes are reused without inference; explicit rerun remains available.
