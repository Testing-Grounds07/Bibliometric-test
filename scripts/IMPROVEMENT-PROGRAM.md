# Research views, checks and verification

## A short guide for researchers

| View or check | What it tells you | What it does not establish |
|---|---|---|
| Co-citation / coupling / citation history | Shared foundations, shared reference lists, or documented direct citation paths | Agreement, quality, relevance or causal intellectual influence |
| Validation dimensions | Metadata coverage, solver completion, structural sensitivity, statistical comparison and human interpretation, kept separate | A single overall scientific confidence score |
| Article/network roles | Connectivity, explicit shortest-path brokerage, cores and community participation; PageRank only for directed citation graphs | Importance or impact independent of the relationship and scope |
| Literal term map | Which observed title/abstract phrases occur in the same sources | Author-supplied keywords or semantic equivalence |
| OpenAlex topic map | Which machine-assigned classifier topics occur together | Literal author words or an independently verified ontology |
| MiniLM source-text map | Which source articles have similar pinned title/abstract vectors | Shared citations, agreement or thematic validity |
| Publication windows | Independently rebuilt pairwise co-citation/coupling networks for source publication periods | Historical OpenAlex database snapshots or joint temporal Leiden |
| Publication activity | Concentrations in observed corpus feature share using a bounded Kleinberg batched-document model and simple rate baseline | Global scientific attention, significance, prediction or a breakthrough |
| Collaboration / ego | Stable observed work-specific author or affiliation relationships, or an induced neighborhood of a completed graph | Verified personal identity, direct social interaction or causal collaboration |

The existing score/search distinction remains: the score judges a partition and the search tries to improve it. A good score, stable partition, AI name and researcher interpretation are different things. Unsupported combinations fail explicitly rather than substituting a different algorithm.

### How to inspect evidence

Use **Inspect** with nothing selected for the current map's interpretation and coverage; select a node or line for its actual supporting works. **Analysis** holds the relationship-specific builders and checks. Ordinary visibility, camera, label and cluster filters are display-only.

Article roles distinguish full supplied analytical scope from a displayed subset or capped citation-history result. Path brokerage names its distance assumption. A negligible external link does not automatically make an article a connector. These are exploratory structural descriptions, not validated bibliometric functional classes.

Semantic features and collaboration actors keep typed identities. Terms, topics, people, institutions and countries are not fake scholarly works. Source-text maps can retain normal work-based keyword/AI features; term/topic/actor headings use observed evidence, with unsupported AI descriptions explicitly unavailable. AI names are never validation.

Source-node text/coupling comparisons use the exact common work universe and disclose assigned/unassigned coverage. Reference-to-source and actor-to-source crosswalks use observed citation/authorship membership. They do not compare unlike entity universes with ARI or invent a blended multiplex score. A source can support several actor clusters; cluster source counts overlap and must not be added.

### Time windows and activity

Choose a fixed parent universe or within-parent reselection, explicit publication range/window/step and supported Leiden settings. Each period is actually reconstructed from pinned incidence. Continuity/split/merge tables are many-to-many overlaps with inspectable members and denominators, not permanent identities inferred from matching colors.

Completed period selection and Full pinned map return are display navigation: they do not queue clustering, settings searches, reliability or model naming. Cached matching descriptions remain readable on the full parent; new naming requires an explicit action. A selected period is a read-only analytical context until the full parent is restored.

Activity counts each source once per feature/bin and divides by observed publication exposure. Unknown years and entire missing-metadata bins are not invented zero observations. Partial recent periods, observation dates, metadata availability and sensitivity are shown separately. The original reference is [Kleinberg, section 4: batched documents](https://www.cs.cornell.edu/info/people/kleinber/bhs.pdf).

### Collaboration choices

See [COLLABORATION-MAPS.md](COLLABORATION-MAPS.md) for identity, full/fractional pair counting, publication thresholds, recorded ancestry rollup, team/affiliation sensitivity and human-audited merge/split alternatives. Fractional denominators use the full observed work actor set before the publication cutoff; removed actors' weight is not redistributed. Names are labels, not keys. Human audit rationales/local identities are project-private even when the underlying bibliography is public.

## Provenance, persistence and reuse

- Evidence remains pinned to its identity/checksum and known retrieval date. Unknown legacy dates/queries stay unknown. An immutable run or saved finding is not silently refreshed.
- Audit manifests retain raw support separately from normalized/fractional weights, memberships, seeds, methods, versions and text/model dependencies. Layout and personal display preferences are not scientific cache inputs.
- Compatible network stages can be reused after CPM changes. Reference/text/model changes invalidate their actual dependent stages. Analytical transformations clear dependent reports; display-only transformations retain them.
- Semantic construction, source text/model revision, collaboration metadata/identity policies, temporal settings and burst definitions are versioned. Changed assumptions never inherit a stale successful check.
- Completed scientific reports, full parent/period definitions and evidence pins survive findings and exports. Ego display preferences retain their parent result and deterministic induced selection.
- Protected project requests recheck membership. Project-private imports, screening rationales, audited identities and descendants remain project-scoped. Public-only mathematical reuse does not share findings or personal workspace state.

These changes do **not** activate institutional authentication, multiuser hosting or anonymous fallback. Production institutional deployment still requires its separate reviewed provider/configuration and operational setup. Synthetic test login is limited to the explicitly disposable fixture.

## Safe rollout and rollback

1. Keep the frozen code manifest (`cycle-d-publish.json` or its final successor), current research backup, Neo4j backup and artifact-storage backup together. Preserve older release code and immutable artifact references. No research migration/deletion is part of the UI rollout.
2. Publish only reviewed manifest **code** assets. Trial assets are regenerated from the same shell. Never bulk-copy repository data, project imports, raw metadata, private artifacts or the supplemental sidecar into the web root.
3. The public supplement is opt-in and independently pinned. The staging builder minimizes exactly the already-public 2,855 adaptive work IDs/titles. At runtime retain content-addressed copies outside the web root, for example the host's `private-metadata/<file-sha256>.json`, and point `BIBLIOMAP_PUBLIC_COLLABORATION_METADATA` at that exact immutable file. Preserve prior versions/backups; rerunning extraction must not overwrite the file used by historical results. Preparation time is distinct from a known/unknown retrieval time.
4. Required runtime dependencies include the reviewed legacy service/core/science/native-store helper sources, `scripts/public-collaboration-metadata.mjs`, and the non-static host `analysis-proxy.mjs` alongside its existing `workspace-route-path.mjs` import. The proxy permits only the literal GET route and its single corpus query. The service/helper validates the exact allowlist, approved envelope/types and checksum. No arbitrary file path is accepted from the UI.
5. Root coordinates any loopback legacy service **8094** and host **8080** restarts after all gates. Do not enable the institutional service, change identity configuration, restart the Cloudflare tunnel or change the public URL. Confirm the production proxy chain separately; preview-adapter success alone does not verify it.
6. Verify health, exact public-corpus opt-in delivery, wrong/private corpus denial, write rejection, normal saved-map reopening and the original/trial/history/exploded/3D workflows. Do not print credentials, test-login keys or private logs.
7. Roll back by restoring the previous reviewed code/helper snapshot and exact previous sidecar environment path, then restarting only the same loopback processes. Do not remove or rewrite findings/evidence/artifacts, roll back schema by deletion, or change the tunnel. The storage changes are additive; preserve recoverable files and database backups rather than running cleanup.

Disposable tests and protected fixture cannot share coordinators/artifact roots concurrently. Use only explicitly configured separate disposable Neo4j, never the current research database. Manual cleanup remains separate and reference-checked.
