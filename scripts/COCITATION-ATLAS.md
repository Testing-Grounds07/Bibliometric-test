# Higher-order Atlas pipeline

The static Atlas uses the existing Conservative corpus (2,855 source articles) and reference scopes of 10, 20 and 30 citing articles. Minimum joint support is five distinct source articles. Pairwise edges are filtered before clustering. Higher-order closed frequent sets are mined exhaustively within the 584-reference, ten-citation universe; their maximum size is ten. Closed sets preserve every supported subset without enumerating all subsets individually.

Run from the repository root with the existing `.trials/conservative-cocitation` baseline inputs:

```powershell
python scripts/mine-cocitation-bundles.py .trials/conservative-cocitation/layout-input.json .trials/conservative-cocitation/higher-order-bundles.json
python scripts/mine-cocitation-bundles.test.py
node --env-file=.env.local scripts/extend-cocitation-atlas.mjs
node --test scripts/combined-cocitation-metric.test.mjs
node --env-file=.env.local scripts/combine-cocitation-atlas.mjs
node scripts/verify-cocitation-atlas.mjs
```

The extension script saves 44 new analyses in Neo4j and generates `data.js`, `summary.json`, and `report.html`; it preserves the authored chart UI. Each execution creates new analysis records. Do not rerun `conservative-cocitation.mjs` for UI updates: that original bootstrap script replaces the chart from its historical template.

The combine script must follow the extension script before publication. It adds six combined analyses (50 views total), unifies the UI into a single co-citation method, and defaults to All orders. For updates to just the combined score, run only the combine script; it preserves the original 44 individual-order networks. Combined records point to their underlying individual-order analyses via `DERIVED_FROM`; complete bundle evidence and per-article contributions are retained in their network payloads.

The experimental combined score sums `1 + log2(K - 1)` over distinct co-citing articles, where K is each article's largest qualifying bundle for that pair. This equals pairwise support plus diminishing increments for persistence across higher orders. Counting only the largest order per article avoids inflation from overlapping or nested bundles. It deliberately rewards larger contexts; it is not a validated bibliometric standard, an article count, or a significance test. It does not remove every bibliography-length effect. The chart uses this score for line width; clustering divides it by the product of original reference frequencies. The detail panel preserves raw support, the higher-order bonus, and a nested per-order support profile. Comparisons across reference scopes change the eligible bundles.

For selected order N, eligible closed bundles have at least N references. The chart retains pairs contained in those bundles. Pair support is the deduplicated union of their source articles, divided by the product of the two original reference frequencies for association strength. CPM uses ten starts and mean-edge-weight scaling. Leiden runs on the pair projection, not a hypergraph objective. The UI repacks compact communities and attracts connected communities for readability; positions are not comparable distance measurements across views. Isolated works are retained in pairwise views and labeled unlinked; higher-order views contain only participating works and disclose the excluded count.

## Cluster drill-down

New drill-down levels default to **Expanded** mode: preserve every parent member as an anchor, then add references cited at least five times but below the parent reference-frequency threshold, linked directly to an anchor by at least five co-citing source articles. This is one-hop expansion, not a recursive crawl. **Strict** mode retains only anchors. The added-reference frequency slider and joint-support choices (5 conservative; 3 exploratory) rebuild the actual analytical network, weights, and Auto CPM sweep. Dashed node outlines mark added references. Membership is selected using pairwise support, independently of the displayed order, so high-order views may leave new references unlinked. Changes reset CPM to Auto; manual CPM remains available afterward.

`node --env-file=.env.local scripts/build-expanded-drill.mjs` reconstructs incidence from the exact original 2,855 source IDs, retrieves missing reference labels from OpenAlex, and mines complete closed bundles at support 3 with `mine-expanded-drill.py`. It writes the lazy-loaded `expanded-data.json` (2,192 references at frequency ≥5, 8,495 pairs at support ≥3, 4,668 closed bundles, maximum order 21). Seventy-five references had no returned metadata and retain their OpenAlex ID as label. It does not replace the baseline `data.js`. At drill time, bundle support is recomputed by exact intersection of original source postings, after projecting to the local reference set. Support 5 filters the same complete mined universe. Source bootstrapping remains conditional on the selected reference set/bundles; neighbor inclusion is not re-selected in each sample.

Deploy `expanded-data.json`, the rebuilt worker, `app.js`, `index.html`, `cluster-list.css`, and `exploded-view.js`. The layer inspector honors the chosen support threshold and caps preview enumeration at 2,000 combinations with an explicit warning; shown evidence counts remain complete. Exported bundle evidence is not truncated. Run `node --test scripts/expanded-drill.test.mjs scripts/drill-analysis.test.mjs scripts/exploded-combinations.test.mjs` to check backward-compatible strict support, one-hop membership and threshold behavior. No extra source articles or new Neo4j records are created.

Cluster actions → Explore subclusters freezes the selected community's reference IDs as anchors, preserves the original citing corpus, and runs a new local Leiden sweep. Recursive drill-down records each parent membership, controls, resolution and analysis ID in the export. Breadcrumbs restore the parent controls; scope is locked until returning to the full network. Each new level starts in Auto CPM mode; the adaptive-grid manual CPM slider and both order controls remain available.

`scripts/drill-analysis.mjs` restricts pairwise evidence to the selected references. It projects the complete closed bundles into that reference set, unions supporting articles for identical subsets and their supersets, and rebuilds higher-order edges and capped combined scores. Outside-cluster references cannot provide higher-order bonuses. Original reference frequencies and source-article support are retained, but mean-edge scaling and Leiden communities are recalculated locally. All parent references remain visible, including newly unlinked works. Local CPM values therefore need not produce the same partitions as globally fitted CPM values.

Auto uses the same density-adaptive, fifty conditional source-bootstrap scoring method as the full network. One-cluster and empty results are valid; single-reference communities cannot be drilled into. Low bootstrap agreement is flagged, not treated as proof of meaningful themes. Drill-down is computed in a browser worker, cached for the session, and exported as a derived analysis with a null database analysis ID. It does not overwrite or automatically save new Neo4j analyses. No database or application API is exposed.

Build the local worker with `npx --yes esbuild@0.25.12 scripts/drill-worker.mjs --bundle --format=iife --platform=browser --outfile=public/conservative-atlas/drill-worker.js`. Deploy the bundle alongside `app.js`. Validate with `node --test scripts/drill-analysis.test.mjs`.

### Full-network settings

After generating the original atlas, run `node scripts/build-atlas-settings.mjs`, then `node --env-file=.env.local scripts/save-atlas-settings.mjs`. The first command creates `settings-data.js` with 44 scope/order/cap configurations, density-adaptive candidate resolutions (including the seven legacy values), and 50 deterministic source-article bootstrap samples per tested setting. The second saves the Auto choice and legacy 0.02/0.1 analyses with bundle evidence to Neo4j, reuses unchanged analyses, and records their IDs in the sidecar. Other tested slider settings remain exportable but are not automatically saved. Preserve this sidecar when publishing. Rebuilding it requires rerunning the save step; the save step resumes existing saved IDs.

Auto CPM v3 shares one engine in `scripts/auto-cpm.mjs` between precomputed full-network settings and the drill-down worker. Density uses only linked references and the exact mean-edge-scaled weights supplied to CPM. Selection uses a fixed logarithmic grid spanning density/32 to density×8 at half-octave intervals, plus seven legacy values. Historical refined points remain available manually but cannot affect Auto selection or range qualification. Every tested point uses ten full-data Leiden starts and 50 deterministic source-article bootstrap samples with replacement, with two starts per sample.

The overview score is nonnegative mean bootstrap ARI × retained-reference coverage − 0.20 × introduced tiny-reference fraction − 0.10 × introduced tiny-cluster fraction. Tiny groups contain 1–3 references. Intact disconnected components are exempt, regardless of size. The reference fraction uses all linked references as denominator; the cluster fraction uses only groups created by subdividing a connected component. Adjacent ARI is diagnostic only; there is no forced-split reward. Admissible settings require mean ARI ≥0.70, coverage ≥0.80, introduced tiny-reference fraction ≤0.20 and introduced tiny-cluster fraction ≤0.50. Among settings within 0.05 of the best admissible score, select the fewest clusters; break ties by lower CPM. If no setting is admissible, select the fewest clusters within 0.05 of the best overall score and explicitly disclose unmet safeguards. This fallback does not qualify as a recommendation.

A recommended range must contain the chosen overview, include at least three consecutive eligible fixed-grid points, span a twofold or greater resolution interval, and have every-pair partition ARI ≥0.90. The widest qualifying interval wins. Without such an interval, show “no clear recommendation” and label Auto exploratory. If the admissible choice merely reproduces disconnected components, report no supported internal subdivision. Never switch to a more fragmented partition just to obtain a recommended-range badge. Search-boundary selections are flagged. These defaults prefer overview granularity; they do not impose a target cluster count or guarantee thematic validity.

These are heuristic cutoffs and weights, not CHAMP, significance tests or expert validation. The audit shows density, sampled range, candidate cluster counts, introduced tiny-group fractions, bootstrap coverage, scores and empirical ARI 10th–90th percentiles (not confidence intervals). Reference inclusion, bundle discovery and expanded-neighbor selection remain fixed during resampling. Stability between sampled points is not established. Single-cluster stability alone is not evidence of meaningful subdivision.

Each configuration has its own tested values. Changing scope/order in manual mode selects the nearest tested resolution by log-distance and discloses an adjustment. Legacy 0.02 and 0.1 remain exact. Breadcrumbs restore requested parent settings. Worker progress reports completed candidate counts, without blocking chart controls. Rebuild the worker after modifying the shared engine.

The full build checkpoints to `.trials/conservative-cocitation/auto-cpm-v3-checkpoint.json`; remove or archive that checkpoint before intentionally regenerating changed data/method settings. Sidecar publication occurs only after all 44 configurations finish. For the v2-to-v3 selection-only migration on unchanged data, run `node scripts/reselect-atlas-settings.mjs`: it reuses the existing 50-sample audits and partitions, recomputes component/fragmentation metrics and choices, preserves manual settings, backs up the old sidecar, and saves a before/after comparison. It records a source-data SHA-256 and rejects later reuse if that data changes. The initial v2 migration assumes the existing audits belong to the unchanged atlas; do not use this command after changing evidence. Rebuild fresh instead. Existing analysis IDs are retained for unchanged partitions. The current range/audit is exported with the network; historical Neo4j records are not rewritten merely because the selection method changes. Run `node --test scripts/auto-cpm.test.mjs scripts/atlas-settings.test.mjs scripts/drill-analysis.test.mjs`.

The selected-order slider applies in Single order mode. The maximum-combined-order slider applies in Combined orders mode and caps each article's K before recomputing its logarithmic score, edge normalization, and cluster partition. Cap 2 is equivalent to pairwise weights. Raw article counts remain unchanged. Higher orders remain available according to the chosen reference scope, not according to CPM. Slider positions preview immediately; graph changes apply on release. Manual 0.02 and 0.1 remain available with original memberships preserved for single-order views.

Validate with `node --test scripts/atlas-settings.test.mjs scripts/exploded-combinations.test.mjs scripts/touch-controls.test.mjs`. Deploy `settings-data.js`, `atlas-settings.js`, `touch-controls.js`, `exploded-view.js`, and `exploded-view.css` alongside the existing static files.

In the exploded view, choose a tracked article and enable **Only matching layers** to display only combinations containing it as a real member. Hollow context nodes do not count. The filter covers the full available combination list, including layers not loaded yet, and preserves original combination numbers, article numbers, positions and dotted leaders. Switching the tracked article updates the filter; clearing it restores all layers. This is display-only and does not alter the evidence or analysis. Validate with `node --test scripts/exploded-scroll.test.mjs`.

The shared toolbar separates **Algorithm** from **Network model** (Pairwise, Higher-order, Hypergraph). Existing higher-order scoring is unchanged. Hypergraph + Leiden/Infomap reconstructs complete supported groups and uses a size-normalized two-section with pair contribution `weight / (size - 1)`, equivalent to a weighted incident-group/different-member walk. This is explicitly projection-based, not direct hypergraph modularity or memory inference; different hypergraphs may have identical projections. The direct optimizer remains under Experimental objective. Coupling offers pairwise and shared-reference hypergraphs, not n-way co-citation. Original pair lines, inspectors, filters and bridge-role semantics stay unchanged; envelopes default on in Hypergraph mode. Model and groups are retained in tab sessions and saved project findings. Projection reliability bootstraps whole groups using the selected algorithm; Find settings searches projection-specific CPM or Markov time. Its Leiden starting CPM is projection density / 4, not the ordinary cached Auto recommendation. Validate with `node --test scripts/hypergraph-network.test.mjs scripts/network-reliability.test.mjs scripts/method-settings.test.mjs`.

The **3D** canvas option lazily loads a local Three.js WebGL renderer with orbit/pan/pinch controls and keyboard rotation/zoom. Compact diamonds are hyperedge hubs, not articles. **Explode layers** animates complete combinations onto parallel planes; repeated article copies retain aligned positions and dotted identity guides. Article tracking uses solid member spheres and hollow context rings; matching-only layers test actual membership. Filtering, search, selected articles/connections and cluster visibility restrict the preview without altering the analysis. Preview defaults to eight groups, selectable as 4/8/16, covers cluster combinations before filling with strongest remaining groups, and reports complete/eligible counts. Groups over 240 members and previews over 1,600 member occurrences are refused whole, never clipped. Depth and 3D line appearance are illustrative, not quantitative similarity or citation strength. Exact evidence and the original continuous exploded article list remain accessible. Rendering failure leaves an explanation and the Network button available; 2D SVG export is disabled while 3D is active. Camera motion respects reduced-motion and Pause motion. Three.js 0.186.1 is pinned; retain `THREE-LICENSE.txt` when deploying. Build `scripts/hypergraph-3d.mjs` as an IIFE bundle with an external source map.

`public/conservative-atlas/methods-explained.html` is a self-contained offline animated guide with no external runtime dependencies. It distinguishes conceptual Leiden stages, a genuine weighted toy random walk / stationary map-equation calculation, and hypergraph groups versus their pair projection. Its CPM slider compares four example partitions, not the full Leiden optimizer or a real-corpus recommendation. All numerical examples are explicitly toy data. Open it from **More → Resources → Animated method guide**, or as a local file. Validate with `node --test scripts/hypergraph-3d.test.mjs`.

Bundle deletion follows analysis/project deletion. Original corpus and analysis records remain available.
