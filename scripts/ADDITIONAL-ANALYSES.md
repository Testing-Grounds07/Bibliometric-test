# Additional network analyses

The shared co-citation and coupling canvas now offers **Nested block model · hierarchy** in Community method. **Analysis → Additional analyses** contains Unusual connections, Network backbone, Research over time, hierarchy-level selection, and JSON export. Calculations use the analytical graph before cluster, query and line-display filters.

## Unusual connections

The incidence matrix is formed from reference-to-source lists for co-citation and source-to-reference lists for coupling. Opposite-side nodes are grouped by their degree within the selected node universe. For each displayed analytical pair, a one-sided hypergeometric survival probability is calculated in every degree stratum capable of containing a shared neighbor. The minimum stratum probability is Bonferroni-corrected across these strata, then Holm-corrected across all possible unordered pairs in the selected node universe. Pairs outside the analytical edge set receive p=1 for correction. This retains a conservative test family even when support thresholds have already selected candidates.

The result answers whether a pair has unusually high overlap in at least one degree stratum, conditional on this corpus and scope. It does not test a whole higher-order combination, thematic relevance or causation. The degree strata can be small and the combined corrections conservative. Passing edges are available as a display filter and adjusted probabilities appear in line inspection. This does not rerun clustering. Source: [Tumminello et al., statistically validated bipartite networks](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0017994).

## Network backbone

The disparity score at a node of degree k is `(1 - normalizedWeight) ** (k - 1)`, using the full analytical normalized edge strengths. A connection is retained if either endpoint with degree greater than one passes the local threshold. Edges whose two endpoints both have degree one are explicitly retained. A leaf endpoint alone does not guarantee retaining its edge at a hub. These unadjusted local scores are a visualization criterion, not network-wide false-discovery control. Existing display filters also apply; Clear line filter restores their previous behavior. Memberships, reliability and intensity domains remain unchanged. Source: [Serrano, Boguñá and Vespignani, multiscale backbone](https://doi.org/10.1073/pnas.0808904106).

## Research over time

Year windows select source publication years inclusively. Missing years are excluded and counted. Co-citation rebuilds pairwise links on the fixed parent reference universe, with the existing minimum support; references with no links in the period remain available as unlinked nodes. This avoids treating a reference's own publication year as the time when it was co-cited. Higher-order combinations are not mined separately for each window. Coupling windows select source articles and preserve their available reference lists and analytical thresholds.

Each period uses the selected community method. Leiden keeps the current resolution where available; a density-based starting resolution is used when the parent has no CPM. Alternative methods receive their own graph, and block models use the binary eligible topology. Show period applies the result to the shared canvas; Return to parent map restores the saved parent controls and evidence. Changing the community method within a period retains that period. Changing the broader scope/order or rebuilding coupling from its parent inputs starts a new analysis.

Method and hierarchy adjustments replace the current view without adding parent-navigation steps. Returning from a period restores its parent in one action, including the connection-order controls and summary. A hierarchy adjustment on the full map does not create a parent-return button.

Build several windows from the same parent to see membership overlaps with the preceding result. Group numbers are local to each partition. The UI lists the 30 largest overlaps and export retains all of them. Disjoint coupling cohorts have no shared source nodes, so source membership overlap cannot establish continuity between those cohorts. Unequal corpus coverage, incomplete reference lists and citation age affect comparisons; these are descriptive windows, not a dynamic generative model.

## Nested stochastic block model

The official graph-tool engine runs `minimize_nested_blockmodel_dl` with degree correction, three seeded optimization starts, and selects the lowest description length. The model uses the binary topology of eligible analytical connections. Fractional cosine or association weights are not misinterpreted as edge multiplicities; line intensities still show the original evidence weights. Isolated nodes are excluded from inference and remain unlinked in the canvas. Every hierarchy level is projected back to original node IDs and can be selected using the same cluster controls. Block patterns may include core-periphery structure rather than only dense communities. Sources: [graph-tool inference guide](https://graph-tool.skewed.de/static/docs/stable/demos/inference/inference.html) and [official installation instructions](https://graph-tool.skewed.de/installation.html).

The pinned official image digest is `sha256:6998e03f0f47004a580d03ddc3029628631be980b6300c17c1fe937b0286d9fc`; its reported engine version is graph-tool 3.10dev. The version and all three start scores are exported. Optimization starts do not establish the global optimum. The engine selects a hierarchy by description length; CPM and Markov time are not block-model parameters.

Block-model reliability runs on demand with 10 or 50 evidence resamples and two fresh inference starts per resample. It uses the selected hierarchy depth, or the coarsest available level if a resampled hierarchy is shorter. Recovery therefore includes hierarchy-depth variability. The same plain-English Jaccard/retention assessment is used as other methods. It never substitutes a Leiden partition. The prior automatic checks for other methods remain in place.

## Runtime and rebuilding

Run `./scripts/start-blockmodel.ps1` with Docker available. The container publishes only `127.0.0.1:8091`, runs read-only with a bounded temporary directory, two CPUs and 2 GB memory. It mounts the scripts directory read-only and has no database or API credentials. The service accepts only node IDs, edge pairs and two/three starts; requests are limited to 5,000 nodes, 200,000 edges and 6 MB. Only one fit runs at a time, with a 90-second subprocess limit. Cancellation prevents late browser application; an already executing server fit can continue until it finishes or times out. Busy responses are retried briefly. Stop it with `docker stop bibliomap-blockmodel`.

`analysis-proxy.mjs` forwards the exact same-origin `/conservative-atlas/analysis-api/sbm` endpoint to this local service. The repository server imports this proxy; the existing static host imports a copy beside its server. The existing Cloudflare tunnel is retained. A static-only deployment without this proxy/service still supports validation, backbone and time windows with browser community engines, but cannot run block-model inference.

Build and publish `network-extensions-worker.js`, `evidence-explorer.js`, `community-methods.js` (with source map and existing Infomap license/source assets), and `reliability-worker.js` using their corresponding scripts and esbuild. Publish updated app, shell, stylesheet and index assets. Results remain in memory per map; export saves the analysis and evidence audit. No Neo4j data is automatically changed.

Validation includes exact-probability fixtures, multiplicity correction, leaf behavior, temporal incidence reconstruction, source-year selection, unchanged input data, real graph-tool nested-partition consistency, and a real block-model resample. Run `node --test scripts/network-extensions.test.mjs` and set `BIBLIOMAP_BLOCKMODEL_URL` to the local proxy endpoint for `scripts/blockmodel.integration.test.mjs`.
