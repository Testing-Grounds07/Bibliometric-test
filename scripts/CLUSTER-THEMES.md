# Suggested cluster themes

This representation layer never changes edges, community membership, or clustering settings. MiniLM/KeyBERT extraction runs locally during preprocessing. A separate local Qwen3 4B service can describe the selected cluster; phones never download the model. Cluster numbers remain authoritative. Extracted headings remain available as the fallback when generated descriptions are unavailable or evidence is insufficient.

## Grounded descriptions

Displayed cluster headings, extracted keywords and AI concept phrases use shared title-case formatting, including cluster selectors and shared-foundation selectors. Scientific acronyms and established names such as PLS-SEM, AI, MiniLM and KeyBERT retain their capitalization. Formatting is applied at display time, so cached AI names update immediately on refresh while source text, evidence quotations, keyword matching and exported analysis values retain their original spelling.

Accepted generated headings carry a subtle lavender AI badge; keyword and partial-evidence fallback names do not. Separately, cluster cards show the existing method-specific recovery interpretation. Neutral outer node rings repeat that cluster-level rating: solid for mostly holding together, dashed for sensitive boundaries, dotted for substantial changes. No ring means unchecked/checking (or unlinked), never low reliability. Quick results are marked preliminary; tooltips retain small-group cautions. The canvas legend opens the full report. These indicators never change cluster color, membership, node size, edge intensity or layout, and do not rate thematic validity or individual article quality.

Loading a co-citation or source-coupling map automatically queues descriptions for every linked cluster, largest first, using full analytical membership rather than canvas filters. Inspect does not need to be open. Names progressively replace keyword headings while the canvas remains interactive, with a completed/total indicator and retry for unfinished names. Selecting a cluster prioritizes its pending request without interrupting an inference already running. Requests run sequentially and reuse the server cache; changing maps stops the old queue, and returning resumes unfinished work. A compact Inspect card shows a suggested name, commonality sentence, text coverage, and a collapsed concepts/evidence/exception disclosure. Regenerate, Cancel, and Export description remain available. Failed, sparse, or partial descriptions keep keyword headings. Results are suggestions, not validation or reliability scores; an exact excerpt match establishes provenance, not semantic entailment.

The server accepts only known article IDs and memberships for the current corpus, not arbitrary prompts or client-supplied article text. It selects six members nearest the text centroid plus up to six diverse members for abstract evidence, then extends the title overview to at most 48 distinct member titles. Normalized titles are deduplicated only for representation. Titles have explicit evidence keys and can support directly named topics without an abstract. The prompt asks the model to assess recurring title topics first and account for mixed topics. Inspect discloses titles considered and sampled abstracts separately. Up to three neighboring-cluster representatives provide contrast. The model receives truncated available abstracts, extracted keywords and coverage. Coupling subject descriptions are separate from the deterministic shared-foundations list. Missing full text is not fabricated. Subcluster inputs restrict the comparison universe to the sibling partition supplied by the canvas.

Every shared claim must cite at least two member IDs with distinct normalized titles. Exceptions must cite members; contrasts must cite both members and neighbors. The model selects fixed excerpt keys rather than rewriting quotations. Output schemas constrain permitted keys; the server resolves them to original text and verifies article roles and distinct supporting titles. Optional items failing checks are omitted with a disclosure. If the broad summary fails but a narrower concept passes, the card explicitly shows a partial description and keeps the original cluster heading. Otherwise one repair attempt is allowed, identifying how many distinct member works the failed summary actually cited and supplying eligible title evidence for a broader description. The UI retains keywords if that repair fails. Very sparse evidence bypasses generation. These checks do not prove that quotations substantively justify the wording; researcher inspection remains necessary. Article text is treated as untrusted data with no tools or arbitrary execution available to the model.

Cache keys include model/quantization, prompt version, evidence-cache hash, corpus, full partition and selected cluster. Display changes reuse results; membership/text/model changes invalidate them. Completed JSON lives in ignored `.trials/cluster-descriptions`; rejected attempts are local diagnostic artifacts, not returned as successful descriptions. Cancelling or changing maps prevents late results from being applied. One local inference is allowed at a time; concurrent uncached requests receive a retry message. Existing results remain visible when regeneration fails.

### Local runtime

Run `./scripts/setup-cluster-model.ps1`, then `./scripts/start-cluster-descriptions.ps1`. Setup downloads checksum-verified llama.cpp b11701 and the LM Studio community Q4_K_M quantization of Qwen3-4B-Instruct-2507 (2.50 GB), pinned to revision `4edb920b6f14e3b9284d4502a6485103d72cde05`. The model server binds localhost:8092; the evidence/caching service binds localhost:8093. Only the narrowly scoped same-origin `analysis-api/describe` proxy is exposed through the existing site/tunnel, not the general model API. Neither process needs API keys or sends texts to a third-party inference provider. Restart the evidence service after rebuilding metadata caches. Startup is manual, not an installed system service.

The model uses Vulkan offload, six CPU threads, one generation slot and a 16,384-token context. Generation is bounded to 2,000 output tokens and a 180-second request timeout. Runtime logs/PIDs are under `.trials/cluster-model`. Stop the verified service/model processes by their recorded PIDs when no longer needed. The independent block-model service is unaffected.

Run `node --test scripts/cluster-description.test.mjs scripts/cluster-themes.test.mjs`. `node scripts/benchmark-cluster-descriptions.mjs` evaluates twelve real clusters across pairwise, higher-order and source coupling partitions, including a two-member cluster, saving baseline labels, generated output, evidence packets, timing and failures. This is a developer comparison, not a blinded human evaluation.

## Build

Use Python 3.12 with `keybert>=0.9,<0.10`, `sentence-transformers>=5.1,<6`, `transformers>=4.51,<5`, and a CPU PyTorch installation. Dependencies may live in the ignored `.trials/semantic-dependencies` directory. Run `python scripts/build-cluster-themes.py` after building `expanded-data.json`. The script uses existing local metadata; it does not fetch additional OpenAlex records or send article text to an inference service.

The first run downloads `sentence-transformers/all-MiniLM-L6-v2` from Hugging Face with remote code disabled. Its immutable revision is recorded in `.trials/conservative-cocitation/theme-model.json`; model files live under `.trials/semantic-models`. SQLite caches embeddings by model, revision, and input text hash. Long documents are split into 240-token chunks, embedded separately, and mean-pooled/normalized. This avoids relying only on the first 256 tokens. Do not change pooling or encoding without versioning or rebuilding the relevant cache.

Metadata combines cached work records and cited-reference lookups by exact OpenAlex ID, preserving available abstracts. Input is title plus available abstract, never author names. Missing reference text is omitted rather than synthesized. Model embeddings and KeyBERT MMR rank up to 20 literal 1–4-word phrases per reference (diversity 0.3, English stop words). Each phrase retains its field and Unicode-code-point offsets in the original text. Reference embeddings use normalized 384-dimensional vectors, quantized to signed int8 for browser transfer; SQLite retains float32 values. The output `cluster-themes.json` records model revision, package versions, corpus ID, and coverage.

## Browser scoring and interpretation

`cluster-themes.js` aggregates only members of each current nonzero cluster, before display filters. For each retained phrase, term count sums at most three occurrences per reference. The score is:

`(supporting member count / cluster member count) × log(1 + mean cluster total counts / corpus term count) × (0.35 + 0.65 × mean nonnegative KeyBERT relevance) / sqrt(number of clusters containing the phrase)`.

This is c-TF-IDF-inspired, not the BERTopic pipeline or a calibrated probability. For clusters of at least three members, phrases supported by two or more members are ranked ahead of single-document fragments. Preprocessing keeps all title candidates and abstract candidates occurring in at least two documents, reducing one-off fragments and computation. Nested phrases are suppressed, returning up to five nonredundant keywords; fewer are shown if evidence is sparse. Within drill-downs the comparison set consists only of sibling subclusters. A one-cluster view explicitly has no sibling contrast. Coupling now uses cached source abstracts when available: 2,696 of 2,855 source articles in the rebuilt cache.

Up to three representative references are ranked by cosine similarity to the unweighted mean of cached member embeddings. Citation count breaks ties; it does not define representativeness. Repeated normalized titles are suppressed only in this short representative list, never merged in the graph or removed from keyword evidence. Select a cluster to see text coverage, title-only/mixed evidence, keyword evidence buttons, and representative references. Each keyword shows source-text spans with an inspect-reference action. Export theme evidence includes the description, model revision, source text, and analysis setting. Network exports also include theme descriptions. These UI descriptions are not automatically written back to historical Neo4j analyses.

Missing text, English-focused embeddings, tiny clusters, candidate pruning, and abstract availability can bias suggestions. These are exploratory descriptions, not substantive validation or proof that clusters are correct. No comparison to BGE or human coding has been performed.

## Validate and publish

Run `node --test scripts/cluster-themes.test.mjs`. The real-cache test verifies every phrase's literal source span and embedding dimension. Publish `cluster-themes.json`, `cluster-themes.js`, `app.js`, `index.html`, and `cluster-list.css` alongside the existing static atlas. The cache is loaded once and descriptions are recomputed after CPM/order/scope/drill-down changes. Failure to load themes leaves the network usable.

Primary references: [MiniLM model card](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2), [KeyBERT API](https://maartengr.github.io/KeyBERT/api/keybert.html), [BERTopic c-TF-IDF](https://maartengr.github.io/BERTopic/getting_started/ctfidf/ctfidf.html).
